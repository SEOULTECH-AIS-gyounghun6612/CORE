# Docker 컨테이너 환경 최적화 및 구축 프로젝트

## 목표

ROS2 기반 로봇 시스템(제어, 비전 검출, 사물 인식, UI)의 안정적이고 효율적인 컨테이너 운영 환경 구축 및 모듈화.

## 시스템 환경 및 구축 (Environment Setup)

본 프로젝트는 고성능 로봇 제어 및 비전 처리를 위해 Docker 컨테이너를 모듈처럼 교체하며 사용할 수 있는 구조를 제공합니다.

### 1. 컨테이너 이미지 구축 전략

각 작업별 이미지의 일관성과 성능을 위해 다음 사항을 준수합니다.

- 기본 레이어: 비전 처리 및 GPU 가속을 위해 `nvidia-docker` 이미지를 베이스로 사용합니다. (NVIDIA Driver, CUDA, cuDNN 포함)
- 사전 설치 패키지:
  - 시스템 의존성: SSH (포트 2222), UART/Serial 드라이버 등
  - 핵심 소프트웨어: ROS2, OpenCV
- 효율적 빌드: 빌드 시간이 오래 걸리는 패키지는 별도의 빌드 저장소에서 최적화된 옵션으로 관리하여 배포 시간을 단축합니다. (구현 중)

### 2. 네트워크 및 통신 최적화

리얼타임 시스템의 반응성을 확보하기 위해 네트워크 설정을 최적화합니다.

- Host 모드 (`--network host`) 권장:
  - Bridge 모드 대비 5~10%의 처리량 향상 및 지연 시간 오버헤드 제거.
  - 포트 포워딩 설정 없이 Native 수준의 네트워크 성능 보장.
- 포트 관리: 호스트 서비스와의 충돌을 방지하기 위해 컨테이너 전용 SSH 포트(예: 2222)를 할당합니다.

## 모듈형 환경 구축 전략

단일 단말기에서 기능을 분리하여 운영할 때 다음의 가이드를 따릅니다.

### 1. 하드웨어 및 UART 제어

- 장치 접근: UART/Serial 카메라 연결 시 `--device` 옵션을 통해 특정 장치만 노출하거나, 전체 권한이 필요한 경우 `--privileged` 모드를 사용합니다.
- 성능 보장: Docker를 통한 UART 통신은 로컬 환경과 동일한 성능을 제공합니다.

### 2. 데이터 보존 및 볼륨 마운트

- 컨테이너가 교체되더라도 설정 값이나 촬영 데이터가 유지될 수 있도록 호스트 스토리지를 볼륨 마운트(`-v`)하여 사용합니다.

### 3. 권장 실행 커맨드 (Makefile 활용)

설정 파일(`build_config.mk`)에 정의된 변수를 바탕으로 다음 명령을 통해 컨테이너를 실행합니다.

```bash
# 기본 프로젝트(computer_vision) 실행
make run

# 특정 프로젝트 실행
make run PROJECT=my_project
```

내부적으로는 다음의 최적화된 옵션들이 자동으로 적용됩니다.

- `--network host` (지연 시간 최소화)
- `$(DOCKER_DEVICES)` (UART 등 필요한 장치만 연결)
- `-v $(DATA_DIR):$(CONTAINER_DATA_DIR)` (데이터 보존)
- `-p $(SSH_PORT):$(SSH_PORT)` (독립적인 SSH 접속 환경)
